Resources

The course materials are complete on their own: the lectures, the exercises, the case and the cheatsheet are all you need. Everything here is either the official reference you should learn to use, or something extra for when you want to go further.

needed use it during the course  ·  extra only if you want more

Official documentation needed

Learn to read these rather than searching for a blog post. They are written by the people who wrote the code, they match the version you have, and the reference part of them is already on your machine: hovering a name in VS Code shows the same text.

  • docs.python.org  the language and its standard library. The tutorial is a good second pass over Sessions 1 and 2.
  • numpy.org/doc  arrays and linear algebra. Start with NumPy for absolute beginners.
  • pandas.pydata.org/docs  tables. Start with 10 minutes to pandas, which covers most of Session 3 in one page. The user guide explains the ideas; the API reference is what you look details up in.
  • The matplotlib gallery  a wall of example charts, each with the code that made it. Find the picture closest to what you want and read how it was done. This is how everybody learns plotting, including people who do it for a living.
  • The scikit-learn user guide  every model from Session 5 on, each with a page that explains the idea, shows the maths and links to worked examples. The pages the course leans on:

Taking the documentation offline needed

Two things are worth knowing, because there are times you will not have a search box.

The reference is already on your machine. Every package carries its own manual inside it. Hover a name in VS Code, or call help(name) in a cell, and you get the signature and the parameter list. That is the same text the reference pages on the website are generated from.

The full sites can be downloaded. Python publishes its whole documentation as a single archive at docs.python.org/3/download.html, and the NumPy and pandas sites offer offline copies of their versioned documentation too. Worth doing once, in good time, rather than on a day you need it.

Practising with the wifi switched off is a genuinely useful exercise. It is surprisingly quick to get used to help() and hover, and much easier to learn now than under time pressure.

When something has not clicked needed

Almost every beginner gets stuck in the same two places: what a variable actually holds after a line runs, and what a loop is doing on each pass. Reading the code again rarely fixes either. Watching it run does.

  • Python Tutor  paste in a short piece of code and step through it one line at a time. It draws every variable as it changes, and the arrows from names to values are the picture the Session 1 slides use. Free, in the browser, nothing to install. Twenty lines is about the limit, which is exactly the size of the exercises.
  • print is the other debugger. When a loop gives the wrong answer, put a print inside it and run it once. Seeing the wrong value appear on the pass where it first goes wrong is usually the whole diagnosis.
  • For a model that has not clicked, read the book's section for the session (the table above), then the scikit-learn page for the method. Change one setting in the lecture's code cell and run it again: the slide shows what moved.
  • StatQuest  short videos by Josh Starmer that explain cross-validation, ridge and the lasso, logistic regression, trees, random forests and gradient boosting step by step, with pictures. A good second explanation. extra

Revising away from a screen extra

Every lecture and both of the course's reference pages come as PDFs, which is worth knowing before an offline exam. All of them are on the Exam info page.

  • The lectures: every slide, with the result of every code cell. Printing a lecture from the browser leaves those results out, because a code cell only runs once its slide is on screen; the PDFs were made after every cell ran.
  • The cheatsheet: allowed at the exam as a copy saved on your laptop.
  • The maths brush-up, for reading formulas.

More practice extra

Only if you have finished the exercises and want more. None of this is examined.

  • Kaggle Learn  short free micro-courses, each a few hours, that run in your browser with nothing to install. Python, Pandas, Data Visualization, Intro to Machine Learning and Intermediate Machine Learning (pipelines, cross-validation and XGBoost) overlap this course closely and are a good second explanation if something has not clicked.
  • Kaggle datasets  thousands of real datasets to practise on. Pick something you are actually curious about: you will learn more from a question you care about than from another tutorial.
  • Exercism, Python track  small programming puzzles with feedback from volunteer mentors. Good for making the language itself feel automatic.

Machine learning in finance, further extra

Where the methods of this course meet research in finance. Both are long, and both are free working-paper versions.

  • Empirical Asset Pricing via Machine Learning (Gu, Kelly and Xiu, published in the Review of Financial Studies, 2020). Penalised regression, forests, boosted trees and neural networks set against each other on forecasting stock returns: the course's model comparison, at research scale.
  • Financial Machine Learning (Kelly and Xiu, 2023). A survey of what machine learning has been used for in finance and what it has found, written for economists.

Using AI on this course needed

You may use it, and you should learn to. The distinction that matters is between using it to understand and using it to avoid understanding.

  • Good: "explain what this error means", "why does pandas want .copy() here", "give me a hint, not the answer", "what is this function's second argument called".
  • Bad: pasting an exercise and copying what comes back. It reads as though you learned something, right up until the exam, where there is no internet and no assistant.

A fair test: could you now write it again, from a blank cell, without help? If not, you have not finished the exercise.
