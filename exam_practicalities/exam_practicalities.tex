{\LARGE\bfseries\color{ink} Exam practicalities and preparation}\par
\vspace{2pt}
{\color{accent} A short guide for the 180-minute, offline notebook exam}\par
\vspace{7pt}
The exam has two parts worth 50 points each. Work in the supplied answer notebook. This guide sets out what you may use, and helps you prepare your laptop and make your work clear to mark.
\emph{Shortcuts below are for Windows/Linux; macOS users can find the named VS Code commands through the menus or Command Palette.}

\sectionhead{What you may use}
Two things are not allowed: anything that needs the internet, and anything built on AI. Everything else is allowed. This is the official exam cover in short: all aids, no internet, no generative AI.
\begin{itemize}
\item \textbf{Allowed:} your own notes, books and printouts; course materials saved on your laptop (the course ZIP, the lecture PDFs, the cheatsheet); documentation saved beforehand; \texttt{help()} and the documentation VS Code shows when you hover over a name; and \textbf{VS Code's suggestion list}: type \texttt{df.} and it lists \texttt{head}, \texttt{describe}, \texttt{groupby} and the other methods that exist; inside \texttt{pd.read\_csv(} it shows the arguments.
\item \textbf{Not allowed:} anything online (web search, Colab, online documentation, the course site, messages to anyone) and anything built on AI: chat assistants such as ChatGPT, and \textbf{AI code completion}, the grey suggested code that writes a line or a block for you, or writes code from a comment. GitHub Copilot is the best-known example.
\end{itemize}
A quick test for an editor feature: picking a name from a list of what already exists is fine; having code written for you is not. For anything else, use your intuition: \textbf{if it feels like cheating, it probably is.} If you are unsure about a tool, ask before the exam.

\sectionhead{Before the exam}
\begin{itemize}
\item \textbf{Everyone: run the updated readiness check (15 October 2026).} Download a fresh course ZIP or readiness notebook from \href{https://theill95.github.io/mlfin-2026/exam_info.html#readiness}{Exam info}. Open the unzipped folder in local VS Code, select your exam Python kernel, turn off internet, restart the kernel and Run All in \texttt{setup\_check.ipynb}. Read the verdict and confirm the plot appears. A stopped run or kernel crash is not a pass; Colab does not test your laptop.
\item \textbf{Mac users: check XGBoost and LightGBM.} If all checks pass, no additional installation is needed. Only if an error says \texttt{libomp.dylib} is missing/not loaded: reconnect, install \href{https://brew.sh/}{Homebrew} if needed, follow its Next steps, then run \texttt{brew install libomp} in macOS Terminal. For package, architecture or data errors, follow the notebook's matching instructions. After any fix, restart the kernel and repeat Run All offline. See \href{https://theill95.github.io/mlfin-2026/setup.html#macos}{the Mac repair guide}; ask for help before exam day if a problem persists.
\item \textbf{Save your offline materials.} Download the course ZIP and the prepared lecture and cheatsheet PDFs from \href{https://theill95.github.io/mlfin-2026/exam_info.html}{Exam info}. Use these PDFs: printing a live lecture yourself may omit code output. Open saved files with internet off; a bookmark is not an offline copy.
\item \textbf{Know where your files are.} Make one easy-to-find folder for your saved reference materials. Keep the exam files together when you receive them, and check that the notebook can read its supplied CSV locally. Do not rely on Colab, a remote file, or an installation that needs internet.
\end{itemize}

\sectionhead{Use a mock as a rehearsal}
Set aside one uninterrupted \textbf{three-hour block}. Start a timer, turn off Wi-Fi, and use VS Code set up as on page 2. Use only what the exam allows, and keep the mock's code-solutions notebook closed; this also shows whether the materials you saved are the ones you need. Work from the paper and answer notebook as you would in the exam. Save your work and rehearse the two-file hand-in at the end. \textbf{Only after the timer ends}, check the code solutions, compare your reasoning with the questions, and note what to practise next. The supplied mock code solutions deliberately omit written explanations.

\sectionhead{VS Code: switch off AI completion, keep the suggestion list}
As page 1 explains, the suggestion list is allowed and AI completion is not. These steps switch off the one and keep the other. Do them in the VS Code profile and folder you will use for the exam.
\begin{enumerate}
\item \textbf{Switch off the built-in AI.} Press \texttt{Ctrl+Shift+P}, choose \texttt{Preferences: Open User Settings (JSON)}, and add these two entries \emph{inside} the existing outer braces; put a comma after an existing entry if needed.
\begin{lstlisting}[style=vscode]
"chat.disableAIFeatures": true,
"editor.inlineSuggest.enabled": false
\end{lstlisting}
The first is the setting \texttt{Chat: Disable AI Features}: it hides built-in chat and inline AI suggestions and disables the Copilot extensions. The second stops grey suggested code after the cursor, whichever extension would supply it. Neither affects the suggestion list, the argument hints or the hover documentation.
\item \textbf{Disable AI extensions.} Open Extensions with \texttt{Ctrl+Shift+X} and search for \texttt{@enabled}. Use the gear menu to \textbf{Disable} any AI chat, code-generation or completion extension, for example GitHub Copilot, IntelliCode or Tabnine (IntelliCode is AI; IntelliSense, the suggestion list, is not). Keep the Python and Jupyter extensions: they run the notebooks and supply the suggestion list.
\item \textbf{Check it, with Wi-Fi on}, so that an AI extension that needs the internet would show itself. Reopen VS Code, and in a notebook code cell type \mbox{\texttt{import pandas as pd}}, then \mbox{\texttt{df = pd.DataFrame()}}, then \texttt{df.} on a new line. A list with \texttt{head} should appear. Then type the comment \texttt{\# average daily return}, press \texttt{Enter} and wait a few seconds: \textbf{no grey code should appear}. If it does, find the extension that supplies it under \texttt{@enabled} and disable it.
\item \textbf{Followed an earlier version of this guide?} It also switched off the suggestion list. To turn the list back on, delete the other \texttt{editor.} entries it added, keeping \texttt{editor.inlineSuggest.enabled}. If you removed the \texttt{Ctrl+Space} shortcut, open Keyboard Shortcuts with \texttt{Ctrl+K Ctrl+S}, search for \texttt{Trigger Suggest}, right-click it and choose \texttt{Reset Keybinding}.
\end{enumerate}

\sectionhead{While you work}
\begin{itemize}
\item Read each task and its point value. Answer what it asks for: code, a number, a plot, or an explanation. For a plot, give readable axis labels and explain what it shows when asked.
\item Use short cells, clear variable names, and simple checks such as shapes, missing-value counts, or a few displayed rows. Save often. Before finishing, restart the kernel and run the completed notebook from top to bottom to catch missing imports and hidden state.
\item \textbf{If stuck, show your reasoning.} Write the intended calculation or modelling step in a Markdown answer cell, then complete the code you can. Partial work can earn points. If a later part uses an earlier result that may be wrong, state what you are carrying forward and continue; follow-through marking can credit a correct later method.
\item Leave enough time to check that every requested answer is in the answer notebook and that it opens correctly. Do not substitute the question paper or a screenshot for a required file.
\end{itemize}

\sectionhead{The two-file hand-in}
Submit the \textbf{completed answer notebook} and the \textbf{supplied blank one-page PDF}. Put all code and written answers in the notebook. The PDF is intentionally blank and takes no answers. Use the exact filenames printed in your exam instructions, and follow the official submission directions.
